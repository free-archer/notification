# Информатор рабочих встреч

Локальный Linux-информатор, который напоминает о рабочих встречах **за 15 минут, 5 минут, 1 минуту и в момент начала**. Показывает **обязательное окно** поверх остальных и повторяет **системный звук**, пока вы не нажмёте «Понятно».

Работает только в локальной графической сессии (GNOME/Wayland). Браузер, Яндекс Календарь и интернет не нужны — поэтому напоминание не теряется, даже если вы в RDP или сообщение из браузера не видно.

---

## Где хранится файл расписания

```text
~/.local/share/meeting-informer/events.txt
```

То есть полностью: `/home/archer/.local/share/meeting-informer/events.txt`

Откройте его любым редактором или через терминал:

```bash
nano ~/.local/share/meeting-informer/events.txt
```

Только этот файл задаёт, о каких встречах напоминать.

---

## Как пользоваться

**Формат** — одна встреча = одна строка:

```text
YYYY-MM-DD HH:MM | Название встречи
```

Пример:

```text
# комментарии можно — начинаются с #
2026-08-26 14:30 | Планёрка отдела
2026-08-27 09:00 | Встреча с заказчиком
```

- Время — **локальное** время Linux.
- Пустые строки и строки, начинающиеся с `#`, игнорируются.
- Ошибочная строка не ломает приложение — она попадает в журнал.
- Поддерживаются только **разовые** события.

**Способ 1 — вручную.** Отредактируйте файл и сохраните. Информатор сам подхватит изменения за несколько секунд (перезапуск не нужен).

**Способ 2 — по скриншоту (Pi-скилл).** Приложите скриншот Яндекс Календаря и попросите занести встречи. Скилл распознает дату, время и название, сформирует строки и обновит файл через валидатор. Точные дубликаты он не добавляет, существующие строки сохраняет, записывает атомарно и сообщает результат.

**Способ 3 — одной командой.** Можно добавить встречу напрямую через валидатор:

```bash
printf '%s\n' "2026-08-26 14:30 | Планёрка отдела" | ~/bin/meeting-informer-update
```

**Проверить, что всё работает.** Добавьте событие на ближайшую минуту:

```bash
printf '%s\n' "$(date -d '+1 min' '+%Y-%m-%d %H:%M') | Тест" | ~/bin/meeting-informer-update
```

Через минуту появится окно со звуком. После этого уберите тестовую строку из файла.

## Как запустить

Информатор запускается **автоматически при входе в локальную графическую сессию** через пользовательскую службу systemd. Запускать его вручную каждый раз не нужно.

**Статус:**

```bash
systemctl --user is-active meeting-informer.service   # active — работает
```

**Остановить / запустить заново:**

```bash
systemctl --user stop meeting-informer.service        # остановить
systemctl --user start meeting-informer.service       # запустить
systemctl --user restart meeting-informer.service     # перезапустить
```

**Смотреть журнал (запуск, ошибки, срабатывания):**

```bash
journalctl --user -u meeting-informer -f
```

**Отключить автозапуск (если нужно):**

```bash
systemctl --user disable meeting-informer.service
```

Служба: `~/.config/systemd/user/meeting-informer.service`. При ручном запуске из терминала: `~/bin/meeting-informer`.

## Компоненты и тесты

| Файл | Что делает |
|------|-----------|
| `meeting_informer/parser.py` | разбор `events.txt` |
| `meeting_informer/scheduler.py` | точки срабатывания (−15м/−5м/−1м/старт) и отбор созревших напоминаний |
| `meeting_informer/sound.py` | повторяемый системный звук |
| `meeting_informer/app.py` | GTK-цикл и обязательные окна |
| `meeting_informer/updater.py` | CLI-валидатор обновления (для скилла) |
| `bin/meeting-informer` | лаунчер, подхватывает окружение графической сессии |
| `systemd/meeting-informer.service` | пользовательская служба |
| `skills/meeting-informer/SKILL.md` | Pi-скилл для импорта по скриншоту |

Тесты:

```bash
python3 -m unittest discover -s tests
```

## Сборка .deb пакета

Проект готов к упаковке в Debian-пакет. Сборка самодостаточная (не требует `debhelper`), через `dpkg-deb`:

```bash
./build-deb.sh
```

Результат: `dist/meeting-informer_<version>_all.deb`.

Установить:

```bash
sudo apt install ./dist/meeting-informer_*.deb
```

Пакет устанавливает:

- приложение в `/usr/lib/meeting-informer/`;
- лаунчеры `/usr/bin/meeting-informer` и `/usr/bin/meeting-informer-update`;
- пользовательскую службу `/usr/lib/systemd/user/meeting-informer.service`;
- документацию и Pi-скилл в `/usr/share/meeting-informer/`.

`postinst` создаёт шаблон `events.txt` в домашнем каталоге, копирует Pi-скилл в `~/.agents/skills/` и пытается включить и запустить пользовательскую службу для текущего пользователя (`SUDO_USER`). Именно поэтому чтение расписания остаётся по-прежнему `~/.local/share/meeting-informer/events.txt`.

Метаданные пакета находятся в каталоге `debian/` (`control`, `changelog`, `copyright`, `rules`, `compat`). Для сборки по стандартной схеме через `dpkg-buildpackage` понадобится `debhelper`; текущий `build-deb.sh` работает без него.

## Ограничения

- Работает **только в локальной графической сессии** Linux. RDP не используется для показа окон и звука.
- Только разовые события: повторяющиеся встречи и длительность в первой версии не поддерживаются.

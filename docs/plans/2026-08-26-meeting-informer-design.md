# Локальный информатор рабочих встреч: дизайн

**Дата:** 2026-08-26  
**Статус:** согласовано

## Цель

Создать автономный информатор рабочих встреч для Linux. Пользователь вручную поддерживает локальное текстовое расписание или просит Pi-скилл обновить его по скриншоту Яндекс Календаря. Информатор должен напомнить о каждой встрече за 15 минут, за 5 минут, за 1 минуту и в момент начала.

Главное требование: напоминание нельзя случайно пропустить из-за того, что календарь открыт в браузере, браузерное сообщение не видно или пользователь подключился по RDP.

## Ограничения окружения

Целевое окружение на момент проектирования:

- Zorin OS 18.1, база Ubuntu 24.04;
- GNOME;
- локальная графическая сессия Wayland;
- Python 3.12;
- PipeWire с совместимостью PulseAudio;
- доступны `notify-send`, `paplay`, `pactl` и `pw-play`.

Информатор работает только в локальной графической сессии. RDP не запускает его, не является каналом показа окон и не участвует в доставке звука или уведомлений.

## Архитектура

Система состоит из трёх частей:

1. **Фоновое Python-приложение `meeting-informer`** — читает расписание, отслеживает время и показывает обязательные GTK-окна со звуком.
2. **Локальный файл `events.txt`** — единственный источник расписания, доступный для ручного редактирования и автоматического обновления.
3. **Pi-скилл для скриншотов** — анализирует прикреплённый скриншот календаря, преобразует видимые разовые встречи в строки и напрямую обновляет `events.txt` через валидирующий локальный скрипт.

Пользовательский systemd-сервис запускает информатор автоматически после входа в локальную графическую сессию GNOME. Интернет, браузер и Яндекс Календарь не требуются после заполнения файла.

## Формат расписания

Файл: `~/.local/share/meeting-informer/events.txt`

Одна встреча занимает одну строку:

```text
2026-08-26 14:30 | Планёрка отдела
2026-08-27 09:00 | Встреча с заказчиком
```

Формат поля времени: `YYYY-MM-DD HH:MM`. Время интерпретируется как локальное время Linux.

Пустые строки и строки, начинающиеся с `#`, игнорируются. Некорректные строки не останавливают обработку: приложение пишет ошибку с номером строки в журнал и продолжает читать остальные записи. Поддерживаются только разовые события с конкретной датой и временем. Длительность и повторения в первой версии не поддерживаются.

## Поведение информатора

Основной цикл проверяет расписание примерно каждые 10 секунд. Изменение времени модификации файла вызывает его повторное чтение без перезапуска процесса.

Для каждого события вычисляются четыре момента срабатывания:

- `T - 15 минут`;
- `T - 5 минут`;
- `T - 1 минута`;
- `T` — начало встречи.

Когда момент наступил, приложение создаёт отдельное обязательное GTK-окно. Окно:

- отображается поверх остальных окон;
- не закрывается автоматически;
- содержит название встречи и информацию о моменте напоминания;
- имеет кнопку `Понятно`;
- закрывается только подтверждением пользователя или обычным действием закрытия окна.

Звук — системный звук Linux, повторяемый через короткие интервалы, пока окно не подтверждено. Если воспроизведение звука недоступно, окно всё равно показывается и ошибка фиксируется в журнале.

Каждый этап является независимым. Подтверждение сигнала за 15 минут не отключает сигналы за 5 минут, за 1 минуту и в момент начала. Внутри текущего запуска один и тот же этап одного события не создаёт повторных окон.

Прошедшие события не вызывают напоминаний. Уже открытые окна не закрываются при удалении или изменении строки расписания.

## Pi-скилл

Скилл предназначен для работы внутри Pi на этом компьютере. Входом служит прикреплённый скриншот календаря.

Скилл должен:

1. Распознать видимые разовые встречи.
2. Извлечь дату, локальное время и название.
3. Сформировать строки формата `YYYY-MM-DD HH:MM | Название`.
4. Через локальный обновляющий скрипт проверить строки и атомарно обновить файл.
5. Не добавлять точные дубликаты по полной тройке «дата, время, название».
6. Сохранить существующие строки.
7. Вернуть пользователю отчёт о добавленных, пропущенных и ошибочных событиях.

Режим подтверждения не требуется: после распознавания скилл сразу изменяет файл. При невозможности уверенно определить год, дату, время или название скилл не должен молча угадывать; такая встреча попадает в отчёт как ошибка и не записывается.

Обновление выполняется через временный файл и атомарную замену, чтобы информатор никогда не прочитал частично записанное расписание.

## Автозапуск и наблюдаемость

Используется пользовательский systemd unit, запускаемый после готовности графической сессии. Unit должен передавать процессу окружение локальной GNOME-сессии, необходимое для GTK, D-Bus и PipeWire.

Технический журнал доступен через:

```bash
journalctl --user -u meeting-informer
```

В журнале фиксируются запуск, перечитывание файла, ошибки строк, срабатывания напоминаний и ошибки звука.

## Критерии приёмки

- Приложение запускается автоматически при входе в локальную GNOME-сессию.
- RDP не нужен и не влияет на показ информатора.
- Файл читается в согласованном формате.
- Ошибка одной строки не мешает обработке остальных.
- Все четыре этапа срабатывают независимо.
- Каждое окно остаётся до подтверждения.
- Звук повторяется до подтверждения.
- Окна и звук работают в локальной Wayland-сессии.
- Изменения расписания подхватываются без перезапуска.
- Повторная обработка скриншота не создаёт дубликаты.
- Обновление файла атомарно.
- Лог содержит достаточную информацию для диагностики.
- Тестовый режим позволяет проверить сигналы без ожидания 15 минут.

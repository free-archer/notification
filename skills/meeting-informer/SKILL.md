# Информатор встреч: импорт из скриншота

Назначение — распознать встречи на скриншоте Яндекс Календаря и перезаписать расписание локального информатора встреч (`~/.local/share/meeting-informer/events.txt`). При каждом прогоне файл **очищается и заполняется заново** только из распознанных на этом шаге встреч — устаревшие записи удаляются. Информатор затем напомнит за 15 минут, 5 минут, 1 минуту и в момент начала.

## Формат записи

В файле одна встреча занимает одну строку:

```text
YYYY-MM-DD HH:MM | Название встречи
```

Время в файле — **локальное время Linux/пользователя**, а не обязательно время, видимое на скриншоте. Если скриншот показывает другой часовой пояс, перед записью обязательно конвертируй время по настройкам импорта. Пример:

```text
2026-08-26 14:30 | Планёрка отдела
2026-08-27 09:00 | Встреча с заказчиком
```

## Настройки времени для импорта

Перед распознаванием прочитай файл настроек:

```text
/home/archer/.local/share/meeting-informer/settings.conf
```

Формат настроек — `KEY=VALUE`, строки с `#` игнорируются. Текущая настройка пользователя:

```text
SCREENSHOT_TIMEZONE=Europe/Moscow
LOCAL_TIMEZONE=Asia/Novosibirsk
SCREENSHOT_TO_LOCAL_HOURS=4
```

Правило: время на скриншотах Яндекс Календаря считается московским (`Europe/Moscow`, MSK), а в `events.txt` нужно записывать новосибирское локальное время пользователя (`Asia/Novosibirsk`), то есть **+4 часа** к времени со скриншота.

При конвертации учитывай переход даты/месяца/года. Надёжная команда для проверки одной даты:

```bash
TZ="$LOCAL_TIMEZONE" date -d "TZ=\"$SCREENSHOT_TIMEZONE\" 2026-08-27 23:30" '+%Y-%m-%d %H:%M'
# пример результата для MSK -> Новосибирск: 2026-08-28 03:30
```

Если файл настроек отсутствует или неполон — не записывай встречи молча; используй значения по умолчанию выше только после явного указания в отчёте, что настройки восстановлены/использованы по умолчанию.

## Шаги

1. **Определи источник скриншота.**
   - Если пользователь приложил изображение или указал путь к файлу — используй его.
   - Если путь не указан и скриншот не приложен/не вставлен через буфер обмена — возьми самый новый файл-изображение из каталога `/home/archer/Изображения/Снимки экрана`.
   - Для поиска последнего файла используй, например:

     ```bash
     find "/home/archer/Изображения/Снимки экрана" -maxdepth 1 -type f \
       \( -iname '*.png' -o -iname '*.jpg' -o -iname '*.jpeg' -o -iname '*.webp' -o -iname '*.bmp' -o -iname '*.gif' \) \
       -printf '%T@ %p\n' | sort -nr | sed -E 's/^[0-9.]+ //' | head -n1
     ```

   - Если каталог пуст, файла нет или последний файл не похож на скриншот календаря — не угадывай; не записывай встречи и явно сообщи об ошибке источника.

2. **Прочитай скриншот.** Просмотри выбранное/прикреплённое изображение календаря (обычно недельная или дневная сетка Яндекс Календаря). Если использован fallback из каталога скриншотов, укажи путь к файлу в отчёте.

3. **Найди разовые встречи.** Определи видимые встречи. Повторяющиеся (серии) в первой версии не поддерживаются — их пропускай с пометкой.

4. **Определи дату, время и название** для каждой встречи:
   - год — из текущей даты или подписей сетки календаря;
   - дата и время — из ячеек сетки; это время часового пояса скриншота (`SCREENSHOT_TIMEZONE`, сейчас Москва);
   - название — из текста события.

5. **Сконвертируй время в локальное время пользователя.** По текущим настройкам добавь к времени со скриншота 4 часа (MSK -> Новосибирск) или используй `TZ="$LOCAL_TIMEZONE" date -d "TZ=\"$SCREENSHOT_TIMEZONE\" ..."`. Именно сконвертированное время пиши в `events.txt`.

6. **Сформируй строку** `YYYY-MM-DD HH:MM | Название` уже с локальным временем пользователя.

7. **Проверь уверенность.** Если год, дату, время, часовой пояс/смещение или название определить уверенно нельзя — **не угадывай**. Такую встречу не записывай и отметь в отчёте как ошибку.

8. **Передай строки в валидатор в режиме замены.** Отправь строки по одной на строку в stdin команды `/home/archer/bin/meeting-informer-update --replace`. Флаг `--replace` очищает `events.txt` и заполняет его заново только этими строками (сам заголовок-комментарий сохраняется):

   ```bash
   printf '%s\n' \
     "2026-08-26 14:30 | Планёрка отдела" \
     "2026-08-27 09:00 | Встреча с заказчиком" \
     | /home/archer/bin/meeting-informer-update --replace
   ```

   Если строк много — используй временный файл и перенаправь stdin:

   ```bash
   cat /tmp/meetings.txt | /home/archer/bin/meeting-informer-update --replace
   ```

   Не забудь флаг `--replace`, иначе валидатор допишет строки к существующим, а не очистит и перезаполнит файл.

9. **Покажи отчёт.** Валидатор вернёт сводку: «Файл очищен и заполнен заново», «Добавлено», «Пропущено (дубликат в наборе)», «Ошибки». Перескажи пользователю результат: какой файл использован, что старые записи были удалены и файл перезаполнен, какие встречи добавлены, какие вызвали сомнение. Если применялась конвертация времени, укажи правило конвертации (например, `MSK + 4 часа -> Новосибирск`).

## Правила

- Файл `events.txt` очищается и заполняется заново при каждом прогоне (`--replace`); устаревшие записи, отсутствующие на новых скриншотах, удаляются. Заголовок-комментарий с описанием формата сохраняется.
- Дубликаты по тройке «дата, время, название» в одном и том же наборе распознанных строк не записываются повторно — валидатор их отсекает.
- Всегда работай в режиме `--replace`: без него валидатор просто дописывает строки к старым, и файл не очищается.
- Запись выполняется атомарно — информатор не прочитает частично записанный файл.
- Если источник скриншота выбран автоматически, фиксируй путь к нему в отчёте.
- Никогда не записывай московское время со скриншота напрямую, если настройки требуют локальное новосибирское время; сначала конвертируй.
- Сомнительные данные не записывай молча; фиксируй их в отчёте.
